# Папа & Я

Приватное Android-приложение для Михаила и Артура, которое помогает оставаться одной командой, даже когда они живут отдельно.

## Концепция

Приложение не является системой родительского контроля. Основные темы: общение, школа, футбол, шахматы, английский язык, лидерство, совместные миссии и многолетняя история достижений.

## Текущая версия

- Приложение: `0.4.1`
- Android `versionCode`: `15`
- Основной пакет Android: `com.mgtrener.fatherson`

## Технологии

- Expo SDK 57 / React Native 0.86
- Expo Router
- TypeScript
- Supabase Auth + PostgreSQL + Storage + Realtime + Edge Functions
- Expo Notifications для семейных push-уведомлений
- Expo Audio для голосовых историй
- GitHub Actions для проверки и выпуска Android APK

## Основные возможности

- Авторизация и семейная команда с ролями `parent` / `child`.
- Совместные сигналы, встречи, идеи встреч и реакции.
- Голосовые истории и семейная хроника.
- Развитие по направлениям: школа, футбол, шахматы, английский язык и лидерство.
- Достижения, признания, ритуалы, недельные фокусы и письма в будущее.
- Realtime-обновления семейных данных.
- Push-уведомления через Supabase Edge Function.
- Проверка обновлений Android APK и установка новых версий.

## Графика

Утверждённые исходные изображения хранятся в `assets/brand-source/`.

Файлы в `assets/generated/` создаются автоматически скриптом `scripts/generate-brand-assets.mjs` во время установки зависимостей и не коммитятся. Скрипт формирует отдельные PNG для навигации, направлений развития, достижений и служебных иконок, поэтому приложение использует отдельные изображения, а не общий атлас во время выполнения.

## Первый запуск разработчика

1. Установить Node.js 22.
2. Скопировать `.env.example` в `.env`.
3. Заполнить `EXPO_PUBLIC_SUPABASE_URL` и `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` из проекта Supabase `father-son`.
4. Установить зависимости: `npm install`.
5. Запустить `npm run start`.
6. Проверить проект командами `npx expo-doctor` и `npm run typecheck`.

> Репозиторию всё ещё требуется зафиксированный `package-lock.json`. До его добавления CI использует `npm install`; после добавления lockfile нужно перейти на `npm ci`.

## Android APK и обновления

Основная сборка Android выполняется GitHub Actions. Release-пайплайн:

1. Проверяет Expo Doctor и TypeScript.
2. Генерирует Android-проект через Expo Prebuild.
3. Собирает ARM64 release APK.
4. Проверяет, что APK подписан постоянным release-ключом, а не debug-сертификатом.
5. Вычисляет размер и SHA-256 APK.
6. Публикует APK в `MG-Trener/Father-son-releases`.
7. Публикует метаданные обновления в Supabase.

Клиент перед запуском Android-установщика проверяет размер скачанного APK и, если SHA-256 опубликован, сверяет фактический SHA-256 файла с метаданными релиза.

## Supabase

Рабочий проект использует Auth, PostgreSQL, Storage, Realtime и Edge Functions. Семейные данные защищены Row Level Security, а доступ строится вокруг фактического членства пользователя в семье.

Миграции находятся в `supabase/migrations/`. История миграций в репозитории начинается позже первоначального bootstrap схемы, поэтому полное восстановление новой базы только из текущих migration-файлов пока не гарантировано. План восстановления и текущая инвентаризация описываются в `docs/SUPABASE_RECOVERY.md`.

## Безопасность

- В мобильный клиент нельзя помещать Supabase `service_role` / secret key.
- В клиенте используется только publishable key.
- Все прикладные таблицы `public/private`, проверенные 13 сентября 2026 года, имеют включённый RLS.
- Привилегированные операции должны выполняться через проверяемые RPC/Edge Functions, а не доверять `family_id` или роли из интерфейса.
- Скачанный APK проверяется по опубликованным метаданным целостности перед установкой.
