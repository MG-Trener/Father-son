# Выпуск Android APK

## Версии и подпись

`app.json` содержит пользовательскую `expo.version` и целочисленную `expo.android.versionCode`. Для каждого нового устанавливаемого APK versionCode увеличивается. Package: `com.mgtrener.fatherson`.

Все публикуемые обновления подписываются постоянным release-ключом. Сертификат SHA-256: `d87825e9cd301fb6001f4529a6719165e9ab953a47a9782e81009f98a11d988d`. Ключ и пароли хранятся в GitHub Secrets; в репозиторий и публичные артефакты не попадают. Debug APK не публикуется как обновление.

## Автоматический выпуск из main

`.github/workflows/validate-android.yml` проверяет PR. При push в main собирает ARM64 APK, проверяет подпись, публикует `android-v<versionCode>` в **MG-Trener/Father-son-releases** и регистрирует размер, SHA-256 и прямую ссылку в Supabase. Нужны существующие signing secrets, RELEASES_REPO_TOKEN и SUPABASE_RELEASE_SECRET_KEY. Защита от повторной публикации не перезаписывает уже выпущенный тег.

Публичный репозиторий содержит APK; исходный код остаётся в приватном Father-son. Private Storage поддерживается клиентом для прежних выпусков, но новые APK распространяются через публичный GitHub Releases URL.

## Проверяемый выпуск из рабочей ветки

1. Выполнить локальные проверки и отправить commit.
2. Запустить workflow `Signed Test APK` (`preview-brand-branch.yml`) с точной веткой. Сам workflow ничего не публикует в каталог приложения.
3. Дождаться успешного native build и скачать артефакт `papa-i-ya-signed-test-<commit>`: APK, SHA256SUMS.txt и BUILD.txt.
4. Сверить исходный commit, package, versionCode/versionName, постоянный сертификат, SHA-256 и 16 KB ZIP alignment через Android SDK tools.
5. Опубликовать проверенный файл как `papa-i-ya-<version>.apk` в релизе `android-v<versionCode>` публичного репозитория. Не заменять файл существующей версии.
6. Проверить скачивание без GitHub-авторизации и точное совпадение размера/хеша.
7. Добавить метаданные в `app_releases` и проверить клиентский RPC `get_latest_app_release`.

Клиентский канал пока называется `preview`; это имя каталога обновлений, а не тип подписи APK. Обычные функциональные обновления сохраняют minimum_supported_code, поэтому установка остаётся необязательной.

## Проверка пользователем

На обоих телефонах открыть «Настройки → Проверить обновления». Удалять приложение и повторно регистрироваться не требуется. После установки проверить общение между устройствами, системные отступы, галерею и запись голоса. Автоматические и браузерные проверки не заменяют эту проверку нативных возможностей.
