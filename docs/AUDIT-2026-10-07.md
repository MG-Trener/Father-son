## Вывод

Проект содержит действующее Expo/React Native приложение и защищённый Supabase backend. Главный риск — незавершённая доставка изменений: опубликованный APK 0.4.1/15 и `main` не содержат большой набор уже подготовленных исправлений PR #27, тогда как backend уже изменён. Контекст: доступный связанный чат проекта, исходники, PR и документация. Из чата учтено последнее решение владельца работать только в Codex. Полная история старых GPT-чатов проекта недоступна; дополнительные требования из неё не выдумывались. Продукт остаётся пространством общения и совместного развития, без родительского контроля и давления оценками.

## Находки и приоритеты

### P1 — доставка исправлений и проверка на устройствах

В `main` только 32 migration-файла, в production и PR #27 — 50. В #27 также находятся проверки SHA-256 APK, ограничения источника загрузки, RPC-операции встреч, исправления auth bootstrap, typed repositories и тесты. Они не попадают на телефоны, пока нет проверенного нового релиза. Старый APK нельзя считать соответствующим текущей ветке.

Перед выпуском: завершить native build, проверить два ARM64 телефона, поднять версию до следующей свободной пары (например 0.4.2/16 после повторной сверки), сохранить signing certificate, проверить обновление поверх 0.4.1 с сохранением сессии. Затем merge/release. Изменение только source без повышения versionCode не обновит уже установленные приложения.

### P1 — push пока не подтверждён как работающий

`app.json` не содержит EAS projectId и googleServicesFile; `registerPushDevice()` возвращает `project_unconfigured`, а `PushNotificationsBridge` игнорирует результат. Наличие Edge Function `send-family-push` (ACTIVE v3, verify_jwt=true) само по себе не означает доставку на телефон.

Нужны: реальный EAS projectId, корректная Android FCM-конфигурация/credentials, видимый статус регистрации и повторная попытка. Отправку следует перенести из клиентского Realtime callback в серверный outbox: сейчас закрытие отправителем приложения может сорвать вызов Edge Function; повторная выборка ограничена последними 10 минутами/10 событиями. Проверить idempotency, Expo tickets/receipts, отключение недействительных токенов и доставку при закрытых приложениях.

### P1 — оставшиеся advisories npm

После безопасного патча `sharp`: **30 dependency entries**, 19 high / 11 moderate / 0 critical. Это число узлов дерева с унаследованными advisories, а не 30 независимых уязвимостей приложения. Корневые сообщения остаются у `braces`, `node-forge`, `decode-uri-component`, `uuid` и распространяются на Metro/Expo/React Native.

Не применялся `npm audit fix --force`: предлагаемые исправления включают несовместимый откат Expo до 44 и React Native до 0.72 либо переход Router на SDK 58. Нужен отдельный совместимый patch/override review, проверка достижимости уязвимого кода и native CI. Development server доступен только локально; приложение не следует объявлять security-clean только по Expo Doctor.

### P2 — auth lifecycle и восстановление доступа

`src/lib/supabase.ts` включает autoRefreshToken, но нет интеграции `AppState` с `startAutoRefresh/stopAutoRefresh`. Нет UI восстановления пароля. Logout снимает все push devices пользователя и использует глобальный signOut; поведение для нескольких устройств нужно определить явно. В `FamilyContext` асинхронные запросы не защищены от устаревшего ответа после смены пользователя.

Добавить lifecycle listener с очисткой, обработку auth errors, password recovery/deep links, отмену/идентификацию устаревших запросов и регрессионные сценарии logout → другой пользователь, offline → resume, expired session.

### P2 — надёжность записи и времени

`weekly-focus.tsx` пишет weekly focus и activity event двумя запросами; ошибка второго не проверяется. Аналогичные операции следует переводить на атомарные RPC с idempotency keys. В календарных экранах встречаются локальная зона телефона и family timezone: формализовать день/неделю семьи, проверить смену даты и устройств в разных поясах.

### P2 — производительность и архитектура

**Подтверждённый дефект графики:** `scripts/generate-brand-assets.mjs` делит `feature-icons.png` на пять равных вертикальных сегментов, предполагая горизонтальную полоску. Фактический PNG содержит два ряда (школа/футбол, шахматы/английский/лидерство), а имена результатов — home/path/book/together/family. `assets/generated/feature-home.png` содержит обрезанные части книг и шахматной фигуры; дефект виден на экране входа. Нужен проверенный манифест отдельных исходников с правильной семантикой и визуальная проверка всех generated assets, а не только оптимизация размера. PR #25 сохранён для отдельной интеграции рисунков.

`meeting-plan.tsx` — 768 строк. Книга года загружает до 700 growth entries, 300 missions и 500 events и фильтрует историю на клиенте; фиксированные лимиты со временем обрежут ранние годы. Добавить серверный фильтр по периоду, cursor pagination и компактные агрегаты. Realtime должен инвалидировать только затронутые запросы, не всю семью. Продолжать существующий repository/domain слой, не переписывать приложение целиком.

Большие PNG badges (~200 KB каждый) и hero следует оптимизировать по фактическим размерам на экране; проверить качество, cold start, память при записи/воспроизведении и при хешировании APK. SHA сейчас читает весь APK в память.

### P2 — эксплуатация и доступность

У `main` нет branch protection. Настроить обязательные `validate` checks после зелёного CI, запрет force push и правило PR. Не требовать недоступного второго ревьюера при работе одним владельцем.

Security Advisor: один WARN — [Leaked Password Protection Disabled](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Performance Advisor: 58 INFO unused indexes. По отсутствию обращений в небольшой базе индексы не удалялись; structural index checks проходят. Clean-room restore baseline + migrations ещё не доказан. Следующий шаг — локальный Supabase/Docker и регулярное упражнение восстановления, без изменения рабочей базы.

В интерфейсе много текста 8–10 pt; проверить масштаб шрифта, TalkBack, контраст, зоны нажатия 48 dp и клавиатуру. Декоративный зелёный индикатор участника в `UsV2` не связан с presence и не должен создавать ложное впечатление «сейчас онлайн».

## Что остаётся проверить вручную / E2E

1. Два отдельных тестовых аккаунта, создание команды, одноразовый invite, запрет третьего участника.
2. Создание/завершение миссии, встречи и ритуала; повторный тап и повтор после обрыва сети.
3. Голосовая запись, отказ в доступе к микрофону, прерывание, upload/playback на втором телефоне.
4. Письмо до/после unlock date, доступ автора/получателя/постороннего.
5. Push foreground/background/terminated и logout на одном из двух устройств.
6. Обновление APK с тем же сертификатом, отмена установки, неправильный SHA/размер.

Без тестовых учётных записей эти сценарии не выдаются за выполненные; реальные семейные данные не создавались и не удалялись ради теста.
